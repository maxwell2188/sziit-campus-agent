# Trae知识库配置建议

> **文档说明**：火山引擎Trae平台知识库配置指南，用于「深信院校园办事全流程Agent」
> **创建时间**：2026年7月
> **适用场景**：奖助学金/补贴申请、宿舍后勤报修、学业资格与评奖评优自查

---

## 一、知识库整体架构

### 1.1 知识库拆分方式

建议在Trae平台创建 **3个独立知识库**，分别对应3个核心场景，便于分场景绑定和独立优化：

| 知识库名称 | 绑定场景 | 文件数量 | 文档总量 |
|-----------|---------|---------|---------|
| 深信院-奖助学金知识库 | 场景一：奖助学金/补贴申请 | 6个 | 办事规则总览、表格模板库、FAQ问答库、避坑指南、时间节点表、测试用例 |
| 深信院-宿舍报修知识库 | 场景二：宿舍后勤报修 | 6个 | 办事规则总览、表格模板库、FAQ问答库、避坑指南、时间节点表、测试用例 |
| 深信院-学业评优知识库 | 场景三：学业资格与评奖评优自查 | 6个 | 办事规则总览、表格模板库、FAQ问答库、避坑指南、时间节点表、测试用例 |

### 1.2 为什么要拆分3个知识库

1. **检索更精准**：每个知识库聚焦一个场景，减少跨场景干扰
2. **分场景绑定**：Agent可根据用户意图动态选择对应知识库检索
3. **独立迭代**：各场景知识库可以独立更新优化，互不影响
4. **权限管理**：不同部门维护不同知识库，权责清晰

## 三、Trae知识库关键参数配置建议

### 3.1 通用配置（三个知识库通用）

| 配置项 | 建议值 | 理由 |
|-------|--------|------|
| **匹配度阈值** | 0.7（70%） | 校园场景学生提问口语化、表达方式多样，阈值不宜过高，避免漏召回；0.7既能保证相关性，又不会召回太多无关内容 |
| **检索模式** | 语义检索 + 关键词检索（混合模式） | 学生提问既有专业术语也有口语表达，混合模式兼顾两种检索方式的优势 |
| **召回数量** | Top 5 | 文档切片质量较高，Top 5足够覆盖相关内容，太多会增加干扰 |
| **是否开启「仅知识库回答」** | 是（开启） | **强烈建议开启**。校园办事涉及政策规则，准确性要求极高，必须严格基于知识库内容回答，禁止大模型自由发挥编造信息 |
| **未知问题回复话术** | "抱歉，这个问题我暂时还没有找到相关信息，请咨询辅导员或相关部门确认。" | 诚实兜底，明确告知学生不确定，避免误导 |

### 3.2 各场景差异化配置

| 知识库 | 匹配度阈值微调 | 特殊说明 |
|-------|--------------|---------|
| 奖助学金知识库 | 0.68-0.72 | 政策类问题准确性优先，阈值可略高；但学生表达方式多样，不宜过高 |
| 宿舍报修知识库 | 0.65-0.70 | 报修场景口语化程度更高，阈值可略低，提高召回率 |
| 学业评优知识库 | 0.70-0.75 | 学业/评奖问题规则性强，术语相对统一，阈值可略高，保证准确性 |

## 四、文档切片与预处理建议

### 4.1 切片粒度控制

- **目标粒度**：300-500字/块
- **切片原则**：主题单一，一个切片讲清楚一个知识点
- **避免跨主题**：不要把申请条件和材料清单放在同一个切片里

### 4.2 为什么切片要控制在300-500字

1. **检索精准**：块越小，主题越集中，语义匹配越准确
2. **上下文窗口**：Top 5召回时，总字数在2500字以内，不会撑爆上下文
3. **回答聚焦**：Agent可以基于最相关的几个小块精准回答，不被冗余信息干扰

### 4.3 同义词优化

每个文档开头已内置同义词映射表，建议额外在Trae平台配置同义词典：

| 官方标准名称 | 学生常用口语同义词 |
|-------------|------------------|
| 国家助学金 | 助学金、困难补助、补贴、资助、贫困补助 |
| 国家励志奖学金 | 励志奖学金、励志奖、困难奖学金 |
| 国家奖学金 | 国奖、国家奖、最高奖学金 |
| 学业奖学金 | 奖学金、校奖、校内奖学金 |
| 综合测评 | 综测、素质加分、加综测、综合分 |
| 家庭经济困难认定 | 困难认定、贫困认定、建档立卡、低保 |
| 报修 | 维修、修东西、叫师傅、上门修 |
| 毕业资格 | 能不能毕业、毕业条件、学分够不够 |
| 三好学生 | 三好、三好生、优秀学生 |
| 优秀毕业生 | 优毕、优秀毕业、毕业评优 |

## 五、知识库质量验证方法

### 5.1 使用测试用例验证

每个场景提供10条测试用例，建议在知识库上线前逐一验证：

**验证标准**：
- **召回准确率**：10条用例中，至少8条能召回正确的文档切片（Top 3内命中）
- **回答准确率**：Agent基于检索结果给出的回答，政策准确性达到90%以上
- **兜底覆盖率**：超出知识库范围的问题，100%触发兜底话术，不编造信息

### 5.2 验证步骤

1. 将5个正式文档上传到对应知识库
2. 配置好检索参数（阈值、召回数、仅知识库回答）
3. 逐个输入测试用例问题
4. 检查：召回结果是否相关？回答是否准确？不确定的问题是否兜底？
5. 不达标则调整参数或优化文档，直到满足标准

### 5.3 常见问题调优方向

| 问题现象 | 可能原因 | 调优方向 |
|---------|---------|---------|
| 回答不准确，有编造内容 | 未开启仅知识库回答 | 立即开启「仅知识库回答」 |
| 相关内容召不回来 | 阈值太高 / 文档切片太大 | 降低阈值 / 细化切片 |
| 召回太多无关内容 | 阈值太低 / 文档主题不集中 | 提高阈值 / 优化文档结构 |
| 学生口语化提问匹配不上 | 缺少同义词 / 纯语义检索 | 补充同义词典 / 开启混合检索 |
| 回答太啰嗦不直接 | 召回太多 / 文档切片太大 | 减少召回数量 / 缩小切片 |

## 六、知识库迭代更新机制

### 6.1 更新触发条件

1. **政策更新**：学校发布新的奖助政策、管理规定时
2. **发现错误**：学生反馈回答有误、辅导员指出政策不准确时
3. **新增场景**：需要覆盖新的办事场景时
4. **定期复核**：每学期开学前复核一次，确保信息时效性

### 6.2 更新流程

1. 收集最新官方文件
2. 提取更新内容，修改对应Markdown文档
3. 标注更新时间和变更内容
4. 重新上传知识库
5. 用测试用例回归验证
6. 发布更新说明

### 6.3 版本管理

- 每个文档开头标注「官方来源+发布时间」，可溯源
- 重大更新保留历史版本
- 更新日志记录变更内容和时间
